# حلقه‌یار — Android

این پروژه یک پوستهٔ اندرویدی Kotlin دارد و رابط فعلی سایت را داخل WebView امن نمایش می‌دهد. فایل‌های HTML/CSS/JS، تصاویر و فونت‌ها هنگام ساخت از ریشهٔ مخزن به assets اپلیکیشن کپی می‌شوند. در نتیجه رابط داخل APK از نسخهٔ وب مستقل است، ولی هر دو به همان Google Apps Script متصل می‌مانند.

## مشخصات اولیه

- Application ID: ir.halgheyar.app — پس از انتشار اولین نسخه نباید تغییر کند.
- حداقل Android: 6.0 (API 23)
- Java: 17
- WebView محلی با WebViewAssetLoader و آدرس HTTPS محلی
- پل JavaScript محدود برای نسخهٔ بومی: نسخه برنامه، اشتراک‌گذاری، اعلان و به‌روزرسانی APK؛ پیوندهای خارجی در مرورگر سیستم باز می‌شوند.
- بدون اجازهٔ محتوای HTTP ناامن و بدون دسترسی مستقیم به فایل‌های دستگاه
- پشتیبانی از دکمهٔ بازگشت، خطای بارگذاری و تلاش مجدد

## ساخت در Android Studio

1. Android Studio به‌روز را باز کن.
2. پوشهٔ android را باز کن.
3. JDK 17 را برای Gradle انتخاب کن.
4. صبر کن Gradle Sync و دانلود وابستگی‌ها کامل شود.
5. از منوی Build، گزینهٔ Build APK(s) را اجرا کن.

## انتشار و به‌روزرسانی درون‌برنامه‌ای

برای نصب نسخه‌های جدید بدون حذف نسخه قبلی، تمام APKهای عمومی باید با یک گواهی امضای ثابت ساخته شوند. گردش‌کار انتشار امضاشده در `.github/workflows/android-release.yml` آماده شده است؛ اما تا زمانی که کلید امضا و Secretهای GitHub تنظیم نشوند، انتشار عمومی APK فعال نخواهد شد.

1. یک کلید انتشار اختصاصی بساز:
   ```bash
   keytool -genkeypair -v -keystore halqeh-yar-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias halqeh-yar
   ```
2. فایل keystore را به Base64 تبدیل کن و مقدار خروجی را فقط در GitHub Secrets ذخیره کن:
   ```bash
   base64 -w 0 halqeh-yar-release.jks
   ```
3. در مخزن GitHub از مسیر Settings → Secrets and variables → Actions این چهار Secret را بساز:
   - `ANDROID_KEYSTORE_BASE64`
   - `ANDROID_KEYSTORE_PASSWORD`
   - `ANDROID_KEY_ALIAS`
   - `ANDROID_KEY_PASSWORD`
4. فایل keystore و رمزهای آن را هرگز در مخزن یا چت عمومی قرار نده. دو نسخه پشتیبان رمزگذاری‌شده را در دو محل امن جداگانه نگه دار.
5. برای انتشار، یک Tag مانند `v1.0.1` بساز یا گردش‌کار Android signed release را با version name و version code بالاتر اجرا کن.

برنامه نسخه جدید را از GitHub Releases بررسی می‌کند، APK را دریافت می‌کند و نصب‌کننده رسمی اندروید را باز می‌کند. تأیید نهایی نصب و اجازه نصب از این منبع همچنان در اختیار خود کاربر است.

**مهاجرت اولیه:** اگر نسخه نصب‌شده قبلی با کلید Debug ساخته شده باشد، به‌دلیل تفاوت گواهی امضا، اولین نسخه امضاشده ممکن است نیازمند حذف و نصب یک‌باره باشد. پس از نصب اولین نسخه امضاشده، به‌روزرسانی‌های بعدی با همان گواهی روی نسخه قبلی نصب می‌شوند و نیازی به حذف برنامه ندارند.

Application ID و گواهی امضا باید برای تمام نسخه‌های بعدی ثابت بمانند. `versionCode` باید در هر انتشار افزایش یابد.

## همگام‌سازی رابط

برای تغییر رابط وب، فایل‌های ریشهٔ مخزن را ویرایش کن. برای تغییرات مخصوص اندروید، فایل‌های داخل android/app/src/main را ویرایش کن. رابط وب در زمان ساخت APK بسته‌بندی می‌شود.
